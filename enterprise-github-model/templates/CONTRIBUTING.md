# Contributing

1. Check the project's README, issues, and support expectations before starting
   work.
2. Open an issue for significant changes so scope and approach can be agreed.
3. Use a focused branch and pull request. Follow the repository's configured
   checks and review rules.
4. Update tests, documentation, and ADRs when the change affects them.
5. Keep credentials and sensitive data out of commits, logs, and issues.

Signed commits, approval counts, code-owner review, and required CI checks are
enforced only when the repository owner configures the corresponding settings.
